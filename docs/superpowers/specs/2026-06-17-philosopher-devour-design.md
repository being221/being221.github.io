# 🧠 诸子吞噬 — 设计文档

## 1. 项目定位

一个将学习与游戏深度融合的 Web 小游戏。玩家操控一颗"思想种子"在战国大地上吞噬各家学派的思想碎片，通过答题吸收知识、不断成长。核心设计原则：**学习不是障碍，而是变强的途径；答对题是正向反馈，不是门槛。**

## 2. 核心玩法

### 基础概念

- 玩家是一颗"思想种子"，在俯视地图上自由移动
- 地图上散落着各家学派（儒、道、墨、法、兵等）的"思想碎片"
- 靠近碎片触发达题，答对吸收碎片，玩家体积变大
- 体积越大，可以吸收更大的碎片
- 最终目标：集百家之长，成长为参天大树

### 核心循环

```
移动探索 → 碰到碎片 → 弹出题目 → 答对 → 吸收碎片、体积变大
                                    → 答错 → 显示正确答案、继续探索
```

### 游戏流程

```
开局（小种子）→ 吸收基础碎片 → 体积增大
  → 能吸收更大的碎片 → 解锁更深层的题目
  → 打通学派脉络 → 获得学派徽章
  → 集齐所有学派 → 通关
```

## 3. 题目系统（核心差异化）

### 知识树结构

题目按"根→枝→叶→果"四层组织，同一学派的题目之间有逻辑关联：

```
儒家知识树示例：

  [根] 孔子是谁？→ [枝] 什么是"仁"？→ [叶] 孟子如何发展"仁政"？
                                         → [叶] 荀子为何提出"性恶"反对孟子？
                                                         → [果] 儒法之争：荀子学生韩非为何走向法家？
```

### 难度分层

| 层级 | 深度 | 题型 | 碎片大小 | 示例 |
|------|------|------|---------|------|
| 🌱 基础 | 识记 | 谁/什么 | 小 | "己所不欲勿施于人"出自谁？ |
| 🌿 理解 | 关联 | 概念对比 | 中 | "仁"与"兼爱"的根本区别是？ |
| 🌳 应用 | 推理 | 情境判断 | 大 | 孟子用"以羊易牛"劝齐宣王，体现什么策略？ |
| 🏛️ 贯通 | 综合 | 跨学派 | 超大 | 儒法之争的根源是什么？ |

### 关联机制

- 吞下基础碎片后，才会刷出该学派的进阶碎片
- 已解锁的知识卡片在"脉络图"中连成路径，可视化学习进度
- 打通一条完整脉络（根→枝→叶→果），获得学派徽章

### MVP 题库范围

- 5 家学派：儒、道、墨、法、兵
- 每家 6 题：基础 2 + 理解 2 + 应用 1 + 贯通 1
- 共计 30 题
- 题目源文件为独立 `questions.js`，便于持续扩充

## 4. 上瘾机制

### 机制一：问道链（Push Your Luck）

答对一题后，弹出"问道"选项：

```
"还要继续深入吗？"

✅ 继续 → 更难的关联题 → 答对 = 奖励翻倍 (2x→4x→8x...)
         → 答错 = 这一轮的累积奖励全部归零

🛑 收手 → 落袋为安，结算当前累积奖励
```

| 层数 | 题目深度 | 奖励倍率 | 风险 |
|------|---------|---------|------|
| 第1层 | 基础识记 | 1x | 无 |
| 第2层 | 概念理解 | 2x | 答错归零 |
| 第3层 | 关联推理 | 4x | 答错归零 |
| 第4层 | 跨学派贯通 | 8x | 答错归零 |

**设计意图：** "收手还是继续"的犹豫本身就是上瘾核心。每次答对都在强化"我还能再赢"的信念，而答错归零的沉痛让下次更谨慎——形成标准的 Push Your Luck 循环。

### 机制二：连击倍率

屏幕顶部显示实时连击计数：

```
🔥 连击 x7
```

- 每连续答对一题 +1，答错归零
- 连击到 5：屏幕边缘微光特效，"思如泉涌"
- 连击到 10：碎片吸收范围扩大
- 连击到 15：限时稀有碎片自动出现

**设计意图：** 连击越高，沉没成本越大——"现在退出我这 x15 就白攒了"。数字一直在跳本身就是即时正反馈。

### 两种机制的配合

```
碎片出现 → [答对]
              ├─ 连击 +1（数字跳，爽）
              └─ 问道链弹出（"要不要继续？"）
                    ├─ 继续 → 更难题 → 答对=倍率翻倍 → 继续赌？
                    │                → 答错=全部归零
                    └─ 收手 → 落袋为安 → 变大
```

两种机制刚好：连击是**被动积累**（不用想，自动涨），问道链是**主动选择**（你要决定赌不赌）。一被动一主动，节奏刚好。

## 5. 视觉风格

| 元素 | 风格 |
|------|------|
| 地图背景 | 羊皮纸/古地图质感，战国疆域轮廓 |
| 碎片 | 各学派不同颜色光点，大小随难度变化 |
| 玩家 | 一颗发光种子/光球，随体积增大而变化 |
| 连击特效 | 屏幕边缘微光，高连击时金色光晕 |
| 答题界面 | 古简风格，毛笔字体 |
| UI | 顶部：连击计数 + 体积等级；底部：已收集学派进度 |

## 6. 操控方式

| 平台 | 操控 | 说明 |
|------|------|------|
| 电脑 | 方向键 / WASD | 持续按住移动 |
| 电脑备选 | 鼠标点击 | 点击地图位置，种子自动游向该点 |
| 手机 | 触屏滑动 | 手指划过方向即移动方向 |
| 答题 | 键盘 1-4 / 点击选项 | 选择题四选一 |

## 9. 数据模型

```js
// 玩家
player = {
  x, y,           // 位置
  size,           // 当前体积 (5~100)
  level,          // 等级 (1~20)
  combo,          // 当前连击数
  daolian,        // 当前问道链层数 (0=未触发)
  multiplier,     // 当前问道链倍率
  fragments,      // 已收集碎片总数
  schoolProgress: // 各学派进度 {rujia: 4/6, daojia: 2/6, ...}
}

// 思想碎片（地图上的可吞噬物）
fragment = {
  x, y,           // 位置
  school,         // 所属学派 (rujia/daojia/mojia/fajia/bingjia)
  tier,           // 难度层级 (1-4, 对应根枝叶果)
  size,           // 显示大小
  questionId,     // 关联的题目 ID
  color,          // 碎片颜色（按学派）
}

// 题目
question = {
  id,             // 唯一标识
  school,         // 所属学派
  tier,           // 难度层级
  prerequisite,   // 前置题目 ID（null 表示无前置）
  question,       // 题目文本
  options,        // 四个选项 [A, B, C, D]
  correct,        // 正确答案索引 (0-3)
  explanation,    // 解释文本（答错时显示）
}
```

## 10. 游戏循环（每帧）

```
1. 读取输入 → 更新玩家位置
2. 碰撞检测：玩家 vs 碎片
3. 触发碰撞 → 弹出答题界面（暂停游戏）
4. 答题结算：
   - 答对 → 连击+1，问道链弹出
   - 答错 → 连击归零，显示解释
5. 问道链结算（答对后）：
   - 继续 → 下一层题目，倍率翻倍
   - 收手 → 累积奖励结算，玩家变大
6. 刷新碎片（保持地图上 15-20 个碎片）
7. 检测升级/学派完成
8. 渲染：地图 → 碎片 → 玩家 → UI → 特效
```

## 11. MVP 验收标准

- ✅ WASD/方向键控制种子在地图上移动
- ✅ 碰到碎片触发答题弹窗，地图暂停
- ✅ 四种题型四选一，键盘或点击作答
- ✅ 答对：连击+1，问道链弹出
- ✅ 问道链：可选择继续或收手
- ✅ 继续答对 → 倍率翻倍；答错 → 奖励归零
- ✅ 收手 → 结算奖励，玩家体积增大
- ✅ 答错：连击归零，显示正确答案
- ✅ 知识脉络图鉴可查看已收集卡片
- ✅ 连击特效（≥5 屏幕微光，≥10 范围扩大）
- ✅ 打通一家学派（6题全通）→ 获得学派徽章
