## 一个你一定见过的错误

```js
try {
  const traffic = await getTraffic();
  // 期望：一路畅通
} catch (error) {
  // 现实中：堵车了
  console.log("换个路线，或者接受迟到");
}
```

你在写 `try-catch` 的时候，内心其实已经承认了一件事：**有些事情不在你的控制范围之内**。网络会断、API 会崩、依赖的服务会挂掉——你无法阻止这些事情发生，但你可以决定发生之后怎么做。

这恰好是斯多葛学派最核心的思想。

## 控制二分法

公元 2 世纪，罗马皇帝马可·奥勒留在《沉思录》里反复强调一个简单的分类：

> **有些事在你的控制之中，有些事不在。**

- **你的控制范围：** 你的判断、你的选择、你的行动
- **不在你的控制范围：** 别人的评价、天气、经济形势、你的身高、堵不堵车

两千年前的哲学家，其实就是在教你写 `try-catch`。

## 控制二分法 → try-catch

```js
// 斯多葛式的代码结构
function liveDay() {
  try {
    // 你能控制的：做对的事
    actWithVirtue();   // 正义
    showCourage();     // 勇气
    applyWisdom();     // 智慧
  } catch (externalEvent) {
    // 斯多葛派的 catch 块：
    // 承认外部事件不在你控制范围内
    // 然后回到你能控制的——你的判断
    console.log("这不在我控制之内");
    acceptAndMoveOn(externalEvent);
  }
}
```

你**不应该** try-catch 的：
- 别人对你的看法 (`opinionOfOthers`)
- 已经发生的事情 (`thePast`)
- 你的先天条件 (`myInnateAbilities`)

这些是 `finally` 块——无论如何都存在的，去接受它。

## 斯多葛不是"躺平"

很多人误解斯多葛学派是消极的。但它的逻辑恰恰相反：

- 不是"反正控制不了所以无所谓"
- 而是"分清能控制和不能控制的，把 100% 精力放在能控制的部分上"

就像你写代码不会因为网络可能断就不写 `fetch`——你会写 `try-catch`，然后聚焦在**你能控制的业务逻辑**上。

## 一个检查清单

下次遇到让你焦虑的事，运行这个函数：

```js
function stoicCheck(worry) {
  if (isUnderMyControl(worry)) {
    return "行动，别担心";
  }
  return "接受，别纠结";
}
```

如果一件事你改变不了，焦虑只是在浪费 CPU 周期。
